# 得点データ構造とスコアリング

得点記入まわり（`/game/setup` → `/game/score-card` / `/game/simple-score-card` → `/score-view`）
で扱うデータの構造と、アーチェリーの採点ルールをどう表現しているかをまとめる。

## データ構造

スコアシートの見た目そのままに、4階層で持つ。

| エンティティ | 意味 | 主なカラム |
| --- | --- | --- |
| `Game` | 1回の記録（練習・大会）。ラウンドの集まり | `recorded_at`, `game_size` |
| `Round` | ラウンド。エンドの集まり | `number`, `end_size`, `round_size`, `distance_m`, `target_type` |
| `End` | エンド。まとめて射つ矢の1グループ | `number` |
| `Point` | 矢1本。当たった位置と点数 | `number`, `score`, `x`, `y`, `x_cm`, `y_cm` |

サイズを表すカラムは「その1つ下の階層をいくつ含む予定か」を持つ。名前と意味がずれやすいので注意。

- `Game.game_size` … このゲームのラウンド数
- `Round.round_size` … このラウンドのエンド数
- `Round.end_size` … 1エンドの矢数（屋外は6本、インドアは3本が一般的）

いずれも「予定数」であり、実際に記録済みの件数ではない。記入画面の
`ラウンド n/N・END m/M・k/K本` 表示は、この予定数を分母に使っている。

`Round` が距離・的をラウンド単位で持つのは、1つのゲームの中で距離を変える
ラウンド構成（例: 1440ラウンド）を後から扱えるようにするため。現状の設定画面は
ゲーム全体で1つの設定を入力し、`ScoreManager.addRound()` が直前のラウンドの値を
引き継ぐ。

### 位置情報（x / y）

`Point.x` / `Point.y` は、的をタッチして入力したときのタッチ位置を、**的の直径に対する
割合**（左上原点、0〜1）で持つ。`(0.5, 0.5)` が的の中心、`0` と `1` が的の端。
API 側は中心からのずれに `Round.target_type` の的のサイズを掛けて、センチメートル
（`x_cm` / `y_cm`）に変換して保存する。

入力エリアではなく的そのものを基準にするのは、入力エリアは縦長で的は正円なので、
エリア基準だと縦と横で1あたりのセンチメートルが変わってしまうため。的の外をタッチ
した場合は的の縁にクランプする。

`(0, 0)` は「位置情報なし」を意味する。点数だけ入力するモードは常に `(0, 0)` を送り、
その矢には `x_cm` / `y_cm` が入らない。

## アーチェリーのスコアリング

`Point.score` は **点数ではなく当たったリング** を保持する。

| 保存値 | 表示 | 点数 | 備考 |
| --- | --- | --- | --- |
| `11` | `X` | **10** | インナーテン。X の本数は同点時の順位決定にのみ使う |
| `10`〜`1` | `10`〜`1` | 同じ | |
| `0` | `M` | 0 | 外れ |
| 負値 | `M` | 0 | 旧クライアントからの取り込みで、リングが確定できなかった矢 |

つまり **`score` をそのまま合計してはいけない**。X が1本11点として数えられ、
スコアシートの合計と統計値がずれる（6本オールXで 60点 と 66点 が並ぶ）。
変換は次の1か所ずつに集約している。

- バックエンド: `app/core/scoring.py` の `scored_value()` / `scored_value_column()`。
  統計・ランキングの集計クエリはすべてこれを通す。
- フロントエンド: `src/modules/data/score/scoreFunctions.ts` の `scoreToInt()`。
  合計は `totalScore()` を使う。

### 的の種類とリング数

的の一覧は `app/core/target_types.py` と `src/modules/data/score/scoreConfig.ts` に
同じ内容で持つ（追加するときは両方に足す）。`ringCount` は「その的が取りうる点数の
種類数」で、そこから最大点が決まる。

| 的 | `ring_count` | 最大点 |
| --- | --- | --- |
| 92cm / 122cm | 11 | `X`（=11、10点） |
| コンパウンド用(80cm) | 10 | `10` |

リング数が10の的には X がない。点数入力の選択肢も、的をタッチする入力の円の数も、
この `ring_count` から作る。API も、その的が出せない点数（10リングの的への `X` など）を
422 で弾く。

的の円の大きさは実際の的に合わせる。半径を10等分し、中心側から 10, 9, ... 1 とする。
X は独立したリングではなく **10 の内側半分**（半径の 1/20）である。122cm の的なら
10 が半径 6.1cm、X が 3.05cm にあたる。

取り込んだ古いデータは `target_type` が `"unknown"` などリストにない値を持つことがある。
その場合はリング数が分からないので、点数の上限チェックは行わず、表示は標準の的に
フォールバックする。

## 入力中のデータの作られ方

空の記録を残さないため、記入画面は「実際に1本目を記録した瞬間」までデータベースに
書き込まない（`ScoreManager`）。

1. 設定画面から入ると、画面表示用の `Round` / `End` だけをメモリ上に作る（id は `-1`）。
2. 最初の矢を記録したときに `ensurePersisted()` が `Game` → `Round` → `End` を
   まとめて作成し、`gameId` を localStorage に保存する。
3. 「戻る」で1本目より前まで戻ると、その `Game` を削除して未保存の状態に戻す
   （`restartEmptyGame()`）。
4. 「終了」時に、矢が1本も入っていない末尾の `End` / `Round` / `Game` を削除する
   （`discardEmptyTail()`）。1本も記録がなければスコア表示ではなくホームに戻る。

これがないと、記録をやめた・打ち消しただけの「0本 0点」のゲームがスコアログと
統計に残る。

## 入力値の範囲

設定画面と API の両方で同じ範囲を検証する（`app/core/scoring.py` /
`scoreConfig.ts`）。範囲外の値は設定画面で開始ボタンが押せず、API では 422 になる。

| 項目 | 範囲 |
| --- | --- |
| 距離 `distance_m` | 1〜200 |
| 1エンドの矢数 `end_size` | 1〜12 |
| エンド数 `round_size` | 1〜30 |
| ラウンド数 `game_size` | 1〜12 |
| 点数 `score` | 0〜11（かつ的のリング数以内） |
| 位置 `x` / `y` | 0〜1 |
