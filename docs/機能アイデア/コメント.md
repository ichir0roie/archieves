# エンド・ラウンド・ゲームへのコメント

記録に「なぜその点数だったか」を残すための自由記述メモ。
エンド・ラウンド・ゲームのそれぞれに 1 件だけ紐づく。

## データ構造

テーブル定義は共通化する。共通部分は
`app/db/models/comment_model.py` の `CommentMixin`（`user_id` と `body`）が持ち、
各クラスは自分固有のもの（対象へのユニークな外部キーとリレーション）だけを定義する。

| テーブル | 固有カラム |
| --- | --- |
| `game_comments` | `game_id`（unique） |
| `round_comments` | `round_id`（unique） |
| `end_comments` | `end_id`（unique） |

1 対象 1 件なので、保存は常に upsert（既存行があれば更新）。
対象が消えれば `ON DELETE CASCADE` でコメントも消える。

## API

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/games/{id}/comments` | そのゲーム配下の全コメント（ゲーム・ラウンド・エンド）を一括取得 |
| GET / PUT / DELETE | `/games/{id}/comment` | ゲームのコメント |
| GET / PUT / DELETE | `/rounds/{id}/comment` | ラウンドのコメント |
| GET / PUT / DELETE | `/ends/{id}/comment` | エンドのコメント |

スコアシートを描く画面は一括取得の方を使い、1 リクエストで全件読み込む。

## 画面

入力方法は共通で、左側のコメントアイコンを押すとモーダルが開く。
モーダルには既存のテキストが入った状態で表示され、保存するとその行を更新する。
空文字で保存した場合はコメントを削除する。

- 記録入力画面（`/game/score-card`）:
  点数表示の下に、エンド・ラウンド・ゲームの 3 行を置く。
- 記録一覧（`/score-view`）:
  - パソコン: エンドごとの行の右端にコメント列を出す。
  - スマホ: 表に列を足す幅がないので、表の下にエンドごとのコメントをまとめる。
  - ラウンドのコメントは各ラウンドの見出しの下、ゲームのコメントは先頭に置く。

矢を 1 本も記録していなくてもコメントだけは残せる。
空のゲーム・ラウンド・エンドを消す処理（`ScoreManager.discardEmptyTail()` ほか）は、
コメントが付いているものは消さない。
